# LESSONS: pitfalls and insights (append one dated line each; never delete)

- 2026-11-18: Photos are very dark (73–96 % of pixels < 15/255). Whole-frame statistics are mostly background; always use the ROI.
- 2026-11-18: EXP-1 D1A has 24 completely black BLUE-slot frames (LED off until ~13:34) plus one scene-change frame at 14:30 (room lights on). Detect them by pixels, never trust the schedule alone.
- 2026-11-18: D2B and D3A images are stored rotated (4624 px wide). Apply `ImageOps.exif_transpose` and never use orientation or size as a feature.
- 2026-11-18: The capture interval jitters 59–61 s (one 92 s gap in D2A). Do not assign lights with `floor(elapsed/60)`; use the sequence index plus pixel verification.
- 2026-11-18: The spot-count trend flips sign between sessions (D1A +0.94, D1B −0.94). Spot count alone is not an age signal.
- 2026-11-18: White balance was AUTO, so colour ratios may drift; prefer ratios between separately lit frames over within-frame channel ratios.
- 2026-11-18: The system Python (pyenv 3.12) has torch 2.12 globally, but the project must use `.venv` via uv. `python3` from another cwd may resolve to a different pyenv version: always use `uv run`.
- 2026-11-18: Local models already on disk: Ollama (qwen3.5:9b, nemotron-3.5-bolt:e4b, embeddinggemma-2, qwen3-embedding:0.6b) and MLX Gemma-4 e2b/e4b 4-bit under `~/Library/Application Support/Tavys/models/mlx/`. Reuse them, do not download again.
- 2026-11-18: Commit messages must never mention Claude/AI/agents (no Co-Authored-By or 'Generated with' lines).
- 2026-11-18: `uv init --package` in an existing repo leaves README.md untouched but sets the script entry to `foodlens:main`; point it at `foodlens.cli:app`.
- 2026-11-18: Config paths are relative to the repo root (parent of `configs/`); use `cfg.path("data_dir")`. `config_hash` excludes the root, so hashes are machine-independent.
- 2026-11-18: Config sections use `extra="forbid"`: a typo in a YAML key raises `ConfigError` instead of being ignored.
- 2026-11-18: P1 acceptance: the only pixel-vs-schedule mismatches are the 24 DARK D1A blue frames plus the 14:30 D1A room-lights frame, which the dominance rule already rejects as MIXED (dom_ratio well below 0.6). Valid-light mismatches: 0.
- 2026-11-18: Real lit frames have dominance ratio 0.91–0.99, far above qc.dominance_ratio 0.6; the threshold is not sensitive.
- 2026-11-18: exp2_D3A IMG_20260902_134133 (RED) is genuinely defocused (lap_var 2.6 vs median 11.7); it is only a W_BLUR warning. Decide in P2 whether to exclude it.
- 2026-11-18: No raw frame has an EXIF Orientation tag; D2B/D3A are simply stored landscape. Still apply exif_transpose.
- 2026-11-18: `foodlens ingest` rebuilds the manifest and drops QC columns, and `--limit 20` overwrites the full manifest. After any smoke run, rerun full `ingest` then `qc` (both are cached, ~20 s total).
- 2026-11-18: Pillow `draft()` decodes the 16 MP JPEGs at 1/4 scale: ~55 ms/frame at work resolution vs several hundred ms for a full decode.
- 2026-11-18: Weather (Open-Meteo archive, outdoor) gives 25.8–33.9 °C across sessions; D1A/D1B are almost flat (~33.5 °C). This is outdoor air, not room temperature (thermal.indoor_offset_c = 0).
- 2026-11-18: pytest tmp_path contains the test name: never assert on substrings of absolute tmp paths (a test named "..._sorted_..." broke a "_sorted" check).
- 2026-11-18: Plain 2-class Otsu on the lit channel keeps only the brightly lit half of the meat (the LED gradient). The lowest of 3 multi-Otsu thresholds (floored at 8) segments the whole lit surface.
- 2026-11-18: Under BLUE the tray, holder and box walls are lit as brightly as the meat, so per-frame BLUE (and partly GREEN) masks leak into them (IoU vs session ROI 0.33–0.87). RED masks are stable (0.90–0.99), so build the session ROI from RED only.
- 2026-11-18: The meat does not move within a session (RED mask IoU flat over 5.7 h in D3A), so one fixed session ROI per session is valid and keeps R/G/B pixels aligned within a triplet.
- 2026-11-18: Holder/tray material has session-median BLUE/RED 1.5–3 vs meat 0.3–0.45. Remove high-ratio regions that touch the ROI edge only; interior bluish specks (glint streaks, the shadowed lower side in D1B) are meat.
- 2026-11-18: A white top-hat inside a mask makes false glints at the mask's convex corners (bright meat vs dark box). Fill outside-ROI pixels with the ROI median before the top-hat.
- 2026-11-18: On real frames the glint threshold always ends at glint.abs_min = 40 (median + 6·MAD of the top-hat is lower), so abs_min is the parameter that matters.
- 2026-11-18: `foodlens roi` does not touch the manifest (it writes roi_index.parquet), so a roi --limit run needs no ingest/qc rerun; the full run overwrites the --limit index.
- 2026-11-18: Synthetic meat lit equally in all channels has BLUE/RED ≈ 1 and trips the holder rule; tests use level=45 for BLUE frames (real ratio ~0.4).
- 2026-11-18: tests/test_skeleton.py used to run every stub stage with the REAL config and `--limit 20 --force`; once `roi` was implemented it overwrote data/processed/roi_index.parquet. The stub test now uses a tmp config; still re-verify real outputs after check.sh.
- 2026-11-18: Per session×light MADs of mask area/centroid are tiny (≈ 0.5 px, < 0.1 % area), so a raw robust z > 6 flags jitter. The MAD floors (`qc.scene_floor_*`) are the real thresholds: 20 % area, 12 px, 13 % brightness.
- 2026-11-18: Use a centred ROLLING median for scene-change z, not the session median. Sessions have slow trends (D2B meat settles ~23 px in the first 40 min) and persistent steps (D2A +30–65 % brightness at 12:59:32, the 92 s gap) that a session median would reject wholesale.
- 2026-11-18: D1A shows a ~2 % brightness dip in RED/GREEN at ~13:34, when the blue LED was switched on (box opened?). D3A RED drops ~4 % at ~3.6 h. Both are below the 10 % step threshold; watch for them in P3 time series.
- 2026-11-18: Never use GREEN/BLUE per-frame mask geometry as a scene signal: BLUE masks join lit box/tray strips from frame to frame (D1A 14:27:51, centroid z = 32 with the meat unchanged).
- 2026-11-18: The median of uint8 pixels is quantised to whole grey levels (≈ 8 % at BLUE level ~12). Use the mean (or float data) for small relative changes on dim channels.
- 2026-11-18: A stage that rejects on its own outputs must not select its input frames on the final status, or a re-run drops the rejects and un-rejects them. The roi stage selects on `qc_pre_roi`.
- 2026-11-18: Run order is now ingest → qc → roi (roi re-runs qc). qc after roi gives the same result. An old roi_index without `sroi_mean`/`lap_var_roi` is skipped with a warning.
- 2026-11-18: The session ROI covers only 75–90 % of the meat-like region. The dim, shadowed side (RED median 11–18) falls in the lowest multi-Otsu class. This is by design ("well-lit meat"), pending user sign-off.
- 2026-11-18: The glint threshold is the abs_min floor (40) in 75/75 QA panels. On dim BLUE frames the top-hat rarely reaches 40, so the counts drop to 0 while specks remain visible: glint count is confounded with illumination level.
- 2026-11-18: Photo contact sheets at 300 dpi are 3.5 MB each and git-tracked. Use `qa.dpi` = 150 and no SVG.
- 2026-11-18: Two agent sessions (an original and its fork) edited the same EDA files at once and overwrote each other's code and outputs. Only one session may write in this folder; check `ls -lT` times / unexpected diffs before continuing.
- 2026-11-18: Do not inspect the same fixed frames every session. `foodlens eda-sample --tag S<NN>` picks new random + outlier + special frames and logs them; scripts still cover all frames.
- 2026-11-18: Robust z of a smooth series (GLCM contrast MAD ≈ 0.2 %) flags ordinary frames at z > 100. Use relative residuals with a MAD floor (`eda.outlier_floor` = 5 %) and bound the divisor when the rolling median is 0.
- 2026-11-18: Meat brightness falls in 5/5 sessions under all lights, while the lit tray/holder (`ref_mean`) stays flat: the trend is the meat, not LED warm-up. Always keep a non-meat reference when claiming a brightness trend.
- 2026-11-18: Absolute meat brightness differs ~2× between pieces (RED start 38–75) but changes only 2–6 %/h within one: single-shot age needs ratio / normalised features.
- 2026-11-18: The fixed glint floor (abs_min 40) makes counts follow brightness (bright bands over-counted, dim lights under-counted). The relative rule (top-hat ≥ 0.75 × local opening) gives a consistent RED decline (5/5 sessions vs 2/5).
- 2026-11-18: Relative glints produce false hits on the ROI edge next to the bright holder under BLUE (D2B). Exclude an edge band in P4.
- 2026-11-18: The D2A step is +33/+59/+87 % R/G/B inside the ROI (larger than the global-mean +28/+45/+65 %). Meat ÷ surroundings cancels it under GREEN/BLUE but not fully under RED.
- 2026-11-18: The RED-defined shadow is far less dark under BLUE: the LEDs light the meat from different angles, so "shadow" is light-specific.
- 2026-11-18: Executed notebooks that embed full-resolution PNGs exceed the 5 MB limit (03 was 7.7 MB). Embed thumbnails (`show()` downscales to ~1100 px).
- 2026-11-18: Adding a key to the `vision` config section changes the ROI cache hash (roi, vision); the next `foodlens roi` recomputes all masks (~1.5 min). roi_index keeps pointing at the old folder until then, which is fine.
- 2026-11-18: New data (S07): EXP-2 folders were renamed `DATE-…` → `DATE_…` and two session folders are spelled `exp-2_D1A` / `exp-5_D1A`. samples.yaml `folder` paths must match exactly; the pattern fallback now drops hyphens.
- 2026-11-18: The raw data contains byte-identical copies (`IMG_x - Copy.jpg`, `IMG_x(1).jpg`). They shift the R→G→B schedule and double-count frames; ingest rejects them by sha1 (`E_DUPLICATE`), keeping the shortest name.
- 2026-11-18: The fixed session ROI fails in the 16-22 h sessions: the meat slides and shrinks, and the session-median mask becomes a wedge over the tray (exp3). Use per-triplet masks from the triplet's own RED/BLUE frames (`vision/triplet_roi.py`).
- 2026-11-18: As meat darkens with age, the dim lit tray strip falls in the same multi-Otsu class and joins the RED mask through a thin neck. An opening with r=25 px (work res) cuts it; r=15 does not.
- 2026-11-18: EXP-3/4/5 meat fills only 4-7 % of the frame and is fully lit (no shadow zone, `shd_*` NaN in ~42 % of frames); late BLUE frames are so dim they are JPEG-posterised.
- 2026-11-18: A scene "step" can be the meat being moved, not the camera: exp3 19:55 meat +59/+111/+27 % R/G/B vs tray +7-16 %. Always compare meat vs `ref_mean` around a step before calling it a camera artefact.
- 2026-11-18: The step detector runs on the global (tray-dominated) mean, but `step_correct` estimates the gain per column from the ROI values themselves, so a tray-only step (exp5 BLUE) barely changes the meat features.
- 2026-11-18: Full `foodlens features` on 4817 frames takes ~23 min (glint-res loads + two top-hats + GLCM + LBP per frame); it is cached per frame in data/interim/features/<hash>/.
